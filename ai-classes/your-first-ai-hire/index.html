Why an agent is the perfect hire

A chat answers a question. An agent takes a goal and works toward the result: it looks at the situation, decides the next step, does it, and repeats until the job is done.

An agent with no context is a smart stranger. An agent with your context works like a colleague who has been with you for years.

Ten steps, in this order

Hire it
1

Pick one app and learn to drive it.

Claude Cowork is the easiest start, Claude Code gives more control, and Codex or Google's Antigravity work the same way. Learn two keys: / for commands and skills, @ to point at a file. Stay with one app for a full week.

2

Build one folder.

One main folder holds everything: a master file (CLAUDE.md), a memory file (memory.md), a context/ folder about you and the business, one subfolder per business or project, and active/ for one-off jobs. Don't chase the perfect structure. Let it grow.

3

Write the job in one sentence.

List what took you real time last week. Keep the tasks with a finished result that you repeat. Then write it down: "Every Monday, read the supplier inbox and draft replies for my approval."

4

Say what done looks like.

Give it a number, a format and a place to save: "every late shipment from this week, as a one-page table, saved in reports/. Drafts only. Do not send."

Onboard it
5

Let it interview you.

Your agent writes its own onboarding file from your answers. Paste this into a new session:

The interview prompt
Interview me to build my context folder. Ask one question at a time and wait for my answer. Go file by file: about-me, business, offers, ideal-customer, customers, brand-voice, knowledge-base. When my answer is vague, dig deeper. Ask for examples. For brand-voice, ask me to paste 3 texts I wrote. Never guess. If I do not know, write TODO. After each file, show me the draft and wait for my OK. Then save it as context/<file>.md. At the end, write CLAUDE.md.

Answer by voice if you can; it is faster. Then read every line it wrote, because one wrong line about your client spreads into everything it writes. Fix mistakes in the file, not in the chat: the file stays, the chat is gone tomorrow. Test it in a fresh session by asking "who am I and what do I sell?"

Your master file ends up looking like this:

CLAUDE.md
## Who I am. Read context/ before any task. ## How I work. Assumptions are the enemy. If the answer isn't there, ask me. Write in my voice: see brand-voice.md. ## Memory. When I correct you, write the lesson in memory.md. Check it before every task. ## Safety. Drafts only. Never send, never spend.

"Assumptions are the enemy" is Remy's line. It stops most made-up answers.

Train it
6

Keep every session clean.

A long chat gets worse with time. Start each task in a clean session (the commands are in the next section).

7

Let it learn from your corrections.

Each time you correct it ("price always on page 2"), it writes a dated one-line rule in memory.md and checks it before the next task. Read the file every week and delete rules that are old or wrong.

Equip it
8

Give it access, slowly.

Connect one app first, usually email or calendar, and test it read-only: "List my five most recent emails. Do not reply." Permissions grow with trust, from read-only to asking before each action to always allowed. Spending money always stays with you.

Delegate
9

Save the method as a skill.

Do a job once with the agent, then say "make this a skill". It saves a SKILL.md file with the steps, and next time one word runs it. After each run, say "update the skill with what we changed". Remy says most of his good skills reach version 5 to 10.

10

Give it a routine.

Schedule the skill. A good first one for a supply chain or logistics team: at 8:00, 13:00 and 17:00, read new supplier and carrier email, sort it (urgent, reply, FYI, spam), draft replies in your voice, and report what needs you today. It never sends. You approve.

The commands that keep it sharp

These are Claude Code commands. Other apps have their own versions, but the ideas are the same.

/context
shows how full the agent's working memory is. Check it before every task.
/compact
summarises the conversation so far and keeps going. Use it when the session gets crowded.
/clear
wipes the chat and starts fresh. Your files stay.
/memory
opens your memory files so you can read and fix the rules.
@brand-voice.md
loads one exact file, so the agent doesn't search for the wrong one.
/resume
picks up an earlier session.
Esc Esc
rewinds to an earlier message.
"Write handoff.md"
before you clear: what was done, what is open, what comes next. Next session: "@handoff.md, let's continue."

And four lines to add to your master file so it doesn't make things up: never invent names, numbers, quotes or links; if you are not sure, say so and ask me; name the file or link next to every fact; list your assumptions before you start.

You still check names, numbers and dates, always, before anything leaves your desk.
